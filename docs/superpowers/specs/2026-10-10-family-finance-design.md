# 家庭账本（HearthLedger）设计文档

- 日期：2026-10-10
- 状态：已评审，待用户最终确认

## 1. 背景与问题

用户对家庭财务缺乏清晰认知，存在四大困惑：

1. 钱都花去哪了
2. 家里到底有多少钱
3. 能不能存下钱
4. 家人花钱不透明

家庭结构：五口之家（用户、妻子、女儿、父母）。本期聚焦用户 + 妻子（女儿体现为开销）。父母退休、每月约 1k 收入、经济基本独立，暂不纳入。

收入：家庭年收入约 55 万；妻子有零散补课收入（后续可加入）。

## 2. 目标

搭建一个本地 Web 应用，让用户能够：

1. 快速手动记账（收支），金额记整数元即可，不追求精确到分
2. 登记资产/负债，自动计算净资产
3. 生成报表，看清钱花哪了、结余多少、净资产多少
4. 数据模型从第一天起预留「归属人」维度（我 / 媳妇 / 共同），未来加妻子不用返工
5. 回答「家人花钱不透明」——按成员汇总各自花销

## 3. 关键设计决策（评审后确定）

- **记账口径（简单口径）**：所有花出去的钱都算「支出」，结余 = 收入 − 支出；净资产（资产 − 负债）是独立快照，两者不强制对账。房贷、信用卡还款全额记作支出；负债余额每月手动刷新一次。
- **固定收支**：进入 MVP。提供「复制上月」一键带入上月的固定账，以及固定项模板（工资、房贷、保险等）。
- **颜色**：收入=绿、支出=红（表格与图表一致）；类别用一套稳定的分类色板，全站一致。
- **金额精度**：整数元，金额 ≥ 1 万显示为「x.x万」。

## 4. 范围

### MVP 要做

- 手动记账（收入/支出）：类别、整数金额、归属人、日期、备注
- 资产/负债台账：存款/现金、房产/车、房贷/信用卡/车贷，登记当前估值，自动算净资产
- **流动资产单独展示**（存款/现金），与净资产并列，避免被房产估值带偏
- 报表：分类占比、月度趋势、每月结余、净资产；**按成员（我/媳妇/共同）的支出汇总**
- 预置类别树（两层：大类 + 子类），可自行增删
- **复制上月** + 固定项模板（一键续记）
- 数据备份：应用内「导出备份」（SQLite 备份 + JSON 导出）

### 明确不做（YAGNI，后续再加）

- 微信/支付宝账单导入、自动分类
- 投资/理财跟踪
- 多人登录、手机端适配、局域网访问
- 净资产历史曲线（当前仅展示当前净资产；历史快照留到 v2）

### 后续（v2+）

- 加入妻子：多人、手机端、局域网访问 + 简单登录（两者同版本上线，绝不无鉴权开放 0.0.0.0）
- 投资/理财跟踪
- 净资产历史快照（BalanceSnapshot）
- 周期性固定流水自动生成（v1 先用「复制上月」+ 模板兜底）
- （可选）微信/支付宝账单导入

## 5. 技术栈

- 后端：Python 3 + FastAPI + SQLAlchemy + SQLite + **Alembic**（迁移，从第一天就用）
- 前端：React + TypeScript + Vite + Tailwind CSS + shadcn/ui + **Recharts**（图表统一用它）
- 单机本地运行；SQLite 单文件

选型理由：个人项目、单机使用，这套方案维护成本低；后续升级可平滑替换。

## 6. 系统架构与模块

分层：API 层（FastAPI 路由）→ 业务逻辑层 → 数据访问层（SQLAlchemy）。

模块（每个模块一个清晰职责）：

1. 记账模块（transactions）：收支的增删改查、复制上月
2. 资产/负债模块（balance）：资产负债项登记、净资产与流动资产计算
3. 报表模块（reports）：聚合查询（按时间、类别、成员）
4. 分类模块（categories）：两层类别树
5. 模板模块（templates）：固定项模板、常用项

## 7. 数据模型

### Transaction（流水）

- id、date、direction（income / expense）、amount（整数元）、category_id、owner（me / spouse / shared，默认 me）、note、created_at / updated_at
- **只能挂在叶子类别上**；direction 在记账时为准，Category.direction 仅作筛选与校验

### Category（类别）

- id、name、direction、parent_id（可选）、sort_order
- **深度最多两层**（大类 + 子类），父类不直接挂流水

预置类别：

- 支出：房贷/房租、日常吃喝（买菜 / 外出吃）、孩子（教育 / 兴趣班 / 用品）、交通/汽车、水电煤通讯、购物/网购/娱乐、保险（商业 / 车险）、其他
- 收入：**工资**（用 owner 区分是谁的）、补课、其他

### BalanceItem（资产负债项）

- id、name、kind（asset / liability）、subtype、owner、current_value（整数元）、updated_at、note
- **subtype 按 kind 分开**：asset → 存款 / 现金 / 房产 / 车；liability → 房贷 / 信用卡 / 车贷 / 消费贷
- 净资产 = Σ(asset) − Σ(liability)；流动资产 = Σ(存款/现金类 asset)

### Template（模板）

- id、name、direction、amount、category_id、owner、note、sort_order

## 8. 核心流程

1. 记一笔：打开 → 选收入/支出 → 选类别 → 填整数金额 → 选归属人 → 保存
2. 月初「复制上月」一键带入固定账（工资、房贷、保险等）
3. 报表实时更新；每月底刷新资产/负债余额
4. 定期点「导出备份」

## 9. UI/UX 要点

- 高 UI 要求：shadcn/ui + Tailwind，图表用 Recharts
- 首页 = 概览仪表盘（本月收支、结余、净资产 + 流动资产、分类占比、按成员支出、最近流水）
- 「记一笔」极快：金额自动聚焦、回车即保存、类别图标点选、常用项一键填、默认日期/归属人
- 收入=绿、支出=红，全站一致；类别颜色全站稳定
- 响应式布局（为后续手机端做铺垫，v1 不作硬性要求）

## 10. 错误处理与备份

- 金额校验（正整数）、必填项缺失提示、删除二次确认
- 数据库操作事务化，失败回滚
- 备份：应用内「导出备份」按钮，用 SQLite 的 Connection.backup() / VACUUM INTO 生成一致性快照 + JSON 导出（便于迁移与未来加妻子）

## 11. 测试策略

- 报表聚合金额正确性（单元测试）
- API 接口测试（CRUD、净资产计算）
- 前端关键流程（记账 → 报表更新、复制上月）
